# ELIRAN CRM — PDF Templates Spec

## מטרה
המסמך מגדיר את כללי העבודה והעיצוב עבור מסמכי PDF בפרויקט ELIRAN.

## תבניות רלוונטיות
- `/a0/usr/projects/eliran/templates/pdf/quote_pdf.html`
- `/a0/usr/projects/eliran/templates/pdf/order_pdf.html`

## עקרונות בסיס
- כל מסמך חייב להיות מותאם לעברית ו-RTL.
- הנתונים נשלפים מ-Airtable דרך שכבת ה-backend.
- אין להציג שדות שלא אומתו מול Airtable.
- יש לשמור על קריאות גבוהה גם בהדפסה וגם בייצוא ל-PDF.

## מבנה מומלץ ל-PDF של הצעת מחיר
1. כותרת עליונה:
   - לוגו
   - פרטי חברה
2. פרטי לקוח:
   - שם לקוח
   - כתובת
   - טלפון אם נדרש
   - תאריך
3. כותרת מסמך:
   - שם המסמך
   - מספר הצעה
4. טבלת פריטים:
   - מוצר / דגם
   - כמות
   - מחיר
   - שורה כוללת
5. אזור סיכומים:
   - subtotal אם קיים
   - מע"מ
   - סה"כ
6. אזור תחתון:
   - הערות
   - אחריות
   - חתימה / חותמת

## מבנה מומלץ ל-PDF של הזמנה
1. פרטי חברה
2. פרטי לקוח
3. פרטי הזמנה:
   - מספר הזמנה
   - תאריך
   - סטטוס אם רלוונטי
4. טבלת מוצרים / שורות הזמנה
5. סיכום כספי
6. הערות / תנאים

## עקרונות עיצוב
- היררכיית כותרות ברורה.
- ריווח עקבי בין אזורים.
- טבלאות עם כותרות ברורות.
- יש לשמור על יישור RTL מלא בכל בלוק טקסט.
- צבעים צריכים להיות עקביים עם זהות המותג.
- אין להעמיס אלמנטים דקורטיביים שמפחיתים קריאות.

## נכסים סטטיים
לוגו החברה:
- `/a0/usr/projects/eliran/static/logo.png`

## בדיקות חובה אחרי שינוי PDF
1. לבדוק שהעברית מוצגת נכון.
2. לבדוק שהכיווניות RTL מלאה.
3. לבדוק שאין חיתוך טקסט.
4. לבדוק שכותרות הטבלה מיושרות נכון.
5. לבדוק שסכומים מוצגים באזור ברור.
6. לבדוק שהלוגו נטען מהנתיב הנכון.
7. לבדוק שהשדות המוצגים באמת מגיעים מה-backend.

## מה לא לעשות
- לא לבנות PDF לפני אימות שדות המקור.
- לא להשתמש בשמות שדות שונים בין backend לבין template.
- לא להעמיס מידע עסקי לא רלוונטי למסמך.
- לא לשבור RTL כדי לפתור בעיית CSS נקודתית.
